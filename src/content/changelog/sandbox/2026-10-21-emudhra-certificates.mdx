---
title: Sandbox SDK 0.12.13 stops trusting compromised eMudhra certificates
description: Sandbox SDK 0.12.13 images no longer trust certificates that chain to the compromised eMudhra intermediate CAs. Update your package and image to 0.12.13.
products:
  - sandbox
date: 2026-10-21
---

The private keys of [eight eMudhra intermediate certificate authorities](https://blog.cloudflare.com/emudhra-certificate-compromise/) can be recovered, so anyone can forge a certificate for any hostname that chains to them. Sandbox SDK images up to 0.12.12 trust these certificates. An HTTPS connection that leaves the container directly, such as one from `mountBucket()`, backups, `gitCheckout()`, tunnels, or code that runs in the sandbox, can be intercepted with a forged certificate.

`@cloudflare/sandbox` 0.12.13 and the `docker.io/cloudflare/sandbox:0.12.13` images stop trusting these certificates. The images ship updated Ubuntu and Alpine CA certificates, Node.js 22.23.4, `cloudflared` 2026.10.2, and pip 26.2.2 in the `-python` image. Update the package and the `FROM` line in your `Dockerfile` to 0.12.13, then redeploy.

Bun has no release with a fix yet. Until it does, `bun`, OpenCode, and multipart uploads in `createBackup()` for archives of 10 MiB or more still trust these certificates.

Sandbox SDK 1.x makes no TLS connections of its own, so your image decides which certificates your sandboxes trust. Pull your base image again and rebuild without the Docker build cache, so your image picks up updated CA certificates and runtimes.
